# 本机真实数据库：已完成接入

## 连接与映射

已实际验证 MySQL 8.0.26，地址 `127.0.0.1:3306`，数据库 `media_crawler`，Navicat 连接名 `xy_mysql`。原始配置账号为 root；启动脚本优先使用已有环境变量，缺省采用本机地址、3306、root，**不保存数据库密码**。建议后续创建 SELECT-only 账号，并通过 `MEDIA_CRAWLER_DB_USER` 覆盖 root。

检查时的数据量（会随上游爬虫变化）：

| 表 | 记录数 | 记录定位 ID | 类型 |
| --- | ---: | --- | --- |
| douyin_aweme | 75 | aweme_id | video |
| douyin_aweme_comment | 1557 | comment_id | forum_post |
| weibo_note | 67 | note_id | forum_post |
| weibo_note_comment | 466 | comment_id | forum_post |

四张表映射已写入 config.json，定位 ID 在检查时表内均不重复，create_time 均按 epoch 秒处理。抖音主表当前 aweme_type 全为 0，映射为视频文字说明，不推断媒体像素或音轨内容。评论表没有原帖 URL，不编造链接，可按库/表/comment_id 回查。

检索每次实时读取数据库，不需要重新导入数据。对于已映射表，检索标题、正文，以及表中存在的 `source_keyword` 上游采集主题词；旧配置会根据真实表结构自动识别该列，也可在 `fields.source_keyword` 显式映射其他列名。采集主题词会保留在证据和报告中，它不保证每条正文都包含该词或与主题相关，需要人工核验。**没有将同主题帖子的所有评论自动关联纳入**；仅纳入自身文字命中的评论。因此报告不是采集词对应的全量数据统计，未匹配不能用来断言主题不存在。

例如连续输入「问界m9起火」时，旧版本要求正文或标题包含完整连续短语，即使正文是「问界M9碰撞起火」也不会命中。现在可通过对应的采集主题词找到数据；如上游主题词也不同，可输入「问界 M9 起火」，空格分隔的词按任意词命中，结果会更宽泛。只有 `database.tables` 配置的表参与检索，新平台的表需在配置页检查数据库结构、确认映射后保存。新增记录位于已映射表时无需重启；更新 Python 代码后需要重启 Web 服务和 asyncio 运行时。历史报告是快照，不自动刷新，需要重新点击「开始分析」。

## 现在如何启动

在项目根目录的 PowerShell 执行：

```powershell
.\run.ps1
```

首次在该终端启动会提示 `MySQL password (not saved)`，在本机输入密码后回车。然后打开 **http://127.0.0.1:8000**。启动脚本不会修改 MySQL 数据、账号或权限，不会把密码写入 JSON、文档或报告。

1. 在「配置管理」点击「检查数据库 / 表结构」，应显示 connected=true、configured_mappings_valid=true。
2. 回首页点击「启动系统」，确认五个 asyncio 应用单元均 running。
3. 进入「主题检索」，输入 **高考**，仅勾选「视频字幕」「论坛帖子」。视频字幕在这里包含已有视频标题/说明，不代表已执行语音转写。
4. 点击「开始分析」，检查来源数量、抖音/微博平台、模型情绪判断与原始记录定位。
5. 查看「完整报告」并下载；点击「查看图谱」，选择来源节点核对 `[S1]` 等引用。
6. 在 Navicat 用来源定位核对原记录，例如 `SELECT * FROM media_crawler.douyin_aweme WHERE aweme_id = 实际报告中的ID;`。评论使用实际 comment_id，勿把评论 ID 当成帖子 ID。
7. 进入「论坛监控」启动轮询，观察微博正文及评论、抖音评论的最新窗口；按当前日期查询历史。
8. 停止系统后报告仍保留；终端 Ctrl+C 退出 Web。

只做结构检查：`.\run.ps1 -InspectDatabase`。若使用纯 Python 命令启动而非此脚本，仍需自行设置四个 MEDIA_CRAWLER_DB_* 环境变量。环境变量值在终端和 Web 进程存活期间可用，关闭终端后应重新输入。

## 本次验证说明

历史版本曾通过实际 HTTP 接口启动五个分析工作单元并执行「高考」主题分析，生成 100 条真实来源的报告与图谱；当前运行时已改为 asyncio 协程任务。构成为微博正文 18 条、微博评论 26 条、抖音评论 49 条、抖音视频说明 7 条。逐条使用报告 locator 回查 MySQL，100 条都唯一匹配原记录。图谱包含 103 个节点、102 条关系；论坛轮询也实际读取并记录了 100 条数据库来源，停止服务后报告仍可查询。样本因默认 100 条上限发生截断，报告不是全库统计。

上述历史验证使用第一版词典，100 条规则中性和 low 不能当作真实情绪或风险结论。当前版本已经用大语言模型替换词典，新的结论必须以当前模型、提示词、证据和人工核验为依据；历史规则报告不自动升级为模型报告。

真实连接检查仅读取元数据与记录统计，不修改原库。报告来源是抓取时的历史内容，发布时间不等于报告生成时间；不要将历史数据解释为当前实时舆情。原文、昵称及原始 ID 会保存到本地报告快照，分享报告前请按需脱敏。

完整架构见 `docs/ARCHITECTURE.md`；更换 VM 地址、SSH 隧道、只读账号、映射与排错见 `docs/DATABASE_WORKFLOW.md`。
